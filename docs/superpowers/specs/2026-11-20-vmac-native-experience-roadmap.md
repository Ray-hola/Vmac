# VMac「原生同机体验」路线图

日期：2026-11-20　分支：`ui-native-blue`

这份文档把「原生同机体验」的四层设想，和 VMac 现在的实现逐项对照：哪些已经有，哪些要新做，哪些建议换一种做法，以及按什么顺序做。界面部分的细节在 [界面重做设计说明](2026-11-20-vmac-native-ui-redesign-design.md) 里。

对照所依据的事实来自代码和这台 Mac 上的客机配置（24 GB 内存、10 核；客机 8 GB、5 核、磁盘 100 GB）。

## 1. 逐层对照

### 第一层：视觉与交互

| 设想 | 现状 | 结论 |
|---|---|---|
| 全屏，客机独占一个桌面空间 | 「窗口」菜单里有「进入全屏」，没有按钮和快捷键。全屏后本来就是一个独立的桌面空间 | 新做：工具栏全屏按钮和 `⌃⌘F` |
| 四指轻扫或 `⌃←/→` 在 Mac 和客机之间切换 | VMac 没有截走系统快捷键和系统手势，它们由 Mac 自己处理。所以全屏后，这两种方式应该直接就能切换 | 实测确认；这个设置保持不变 |
| 全屏后用快捷键呼出设置 | 没有 | 新做：`⌃⌘,` 呼出控制中心，以浮层盖在客机画面上，不退出全屏 |
| Retina 自适应分辨率 | 客机显示器已经是 Retina（3840×2400，220 ppi），但「跟随窗口自动调整」是关着的，所以有黑边 | 新做，先验证稳定性 |
| 触控板手势透传 | 客机用的是 Mac 触控板设备，滚动、缩放等手势在客机里可用 | 已有 |
| 防误触的视觉锚点 | 没有 | 新做，见第 2 节 |
| 音频随前台自动切换 | 客机现在没有配置任何声音设备，所以没有声音，也不能用麦克风 | 新做，和「挂起恢复」可能冲突，见第 3 节 |

### 第二层：存储与数据

| 设想 | 现状 | 结论 |
|---|---|---|
| 双向剪贴板 | 文字、图片、文件已经双向同步 | 已有。富文本（带格式的文字）还不支持，作为小项补上 |
| VirtioFS 共享目录 | 没有启用。客机现在没有任何目录挂载，而且「没有挂载」是每次启动时文件边界检查的一部分。底层驱动已经支持给 macOS 客机挂载共享目录 | 新做，见第 4 节 |
| 跨窗口拖拽 | 已有，双向 | 已有，保留 |
| APFS 克隆母盘 | 可以新建和切换虚拟机；新建时是否用了 APFS 克隆还没核实 | 待核实，没有用的话改成用克隆 |
| 稀疏磁盘，上限可指定 | 磁盘按实际用量占空间，装好后可以在界面里扩容 | 已有。补上：安装时就能指定容量，默认 128 GB |

### 第三层：网络与强制代理

现状和设想的做法不同，但目标已经实现，而且更严。**建议保留现状，不改成客机内的 pf 方案。**理由见第 5 节。

### 第四层：算力与生命周期

| 设想 | 现状 | 结论 |
|---|---|---|
| 内存给 Mac 留一半以上 | 已有 CPU 和内存设置，有「不超过本机份额」的上限。这台客机是 8 GB，符合 24 GB 机型分 6 到 8 GB 的规则 | 已有。补上：把「留一半」做成推荐值和明确的提示 |
| CPU 分 2 到 4 核 | 这台客机现在是 5 核（Mac 的一半） | 推荐值改为 4 核，仍可自己调 |
| 所有数字在开始时和之后都能改 | 之后能改；安装时能不能改还没核实 | 补上安装时的选项；设置入口移到「虚拟机与磁盘」 |
| 挂起和恢复 | 没有。底层库支持（需要 macOS 14 以上），但 VMac 没有接 | 新做，先验证，见第 3 节 |

## 2. 视觉锚点

目的是一眼看出自己在客机里，避免把操作做到错的系统上。

- **客机壁纸**：VMac 专属壁纸，深色底配强调蓝，由客机里已有的 VMac 助手设置，不需要用户操作。
- **客机强调色**：按界面重做的主题，设为蓝色。
- **提醒**：Mac 的系统强调色默认也是蓝色。如果两边都是蓝色，强调色起不到区分作用，这时主要靠壁纸。所以在「账户与系统」里提供客机强调色的选择（蓝色、石墨色、橙色），默认蓝色。
- **全屏标识线（可选）**：全屏时在画面最上沿画一条 2 pt 的蓝线。窗口被应用盖满、看不到壁纸时，它仍然可见。默认开，可以关。

## 3. 音频与挂起恢复

两项都是新做，而且很可能互相冲突，所以放在一起。

- **音频**：给客机加上声音输出和麦克风输入。客机的声音会直接混进 Mac 当前的输出设备，不需要切换设备。麦克风需要用户在 Mac 上允许 VMac 使用麦克风。VMac 不在前台时，自动让客机的麦克风静音，回到前台时恢复。
- **挂起和恢复**：关闭 VMac 时把客机的内存状态存到磁盘，下次打开直接恢复现场。存下来的文件大小约等于客机内存（这台是 8 GB）。
- **冲突**：据我了解，苹果的虚拟化框架在保存状态时不支持声音设备，共享目录也可能受限。这一点必须在真机上验证。
- **恢复后的安全处理**：恢复现场后，网络门禁保持关闭，重新通过安全检查后才放行，不能沿用挂起前的授权。

验证方法：做一个只供试验的版本，分别在「有声音设备」「有共享目录」「两者都没有」三种配置下尝试保存和恢复，记录哪些可行、恢复要多久。

如果确实冲突，建议的取舍是：默认开音频，关闭 VMac 时正常关机；在「通用」里提供「挂起而不是关机」的选项，打开时说明客机将没有声音。

## 4. 共享文件夹

- 在「共享与传输」里新增「共享文件夹」，默认关闭。打开时让用户选一个 Mac 上的文件夹，默认是 `~/VM-Shared`。只共享这一个文件夹，客机读不到它以外的任何 Mac 文件。
- 客机里它会出现在 `/Volumes/My Shared Files/` 下面（这是 macOS 客机的固定位置）。VMac 自动在客机桌面放一个名为「共享」的替身，不需要用户在终端里建软链接。
- 可以选「只读」：客机只能读，不能改。
- 文件边界检查从「没有任何挂载」改为「只挂载了用户指定的这一个文件夹」。多出任何其他挂载，检查不通过。
- 它不经过网络，网络门禁关闭时照样能用。
- 提醒写在开关旁边：客机里的任何程序都能读到这个文件夹里的东西，不要放敏感文件。

## 5. 网络：为什么保留现状

**现在的做法**

- 客机只有一块网卡，接在 Mac 上 VMac 自己的一层「网络门禁」上，不经过 vmnet，也没有 `bridge100`。
- 客机发出的每一个连接，都由 Mac 这边的门禁代为拨出，并且只走代理。域名解析也由门禁通过代理完成。IPv6 直接丢弃。UDP 只能经过 VMac 管理的代理核心（Mihomo）转发。
- 门禁默认关闭。每次启动要通过全部安全检查才放行；换节点、授权到期或检查不通过时，门禁立即关闭并断开所有连接。
- VMac 拒绝启动带有其他网卡（vmnet、NAT、共享网络）的虚拟机，所以不存在绕过门禁的第二条路。
- 每次启动都会做一次演练：故意让代理不可用，确认终端、浏览器和域名解析全部失败，并且没有改成直连。今天的启动记录里这一项是通过的。

**和「客机内 pf」方案的比较**

| | 现状：闸门在客机外 | 设想：客机内代理 + pf |
|---|---|---|
| 闸门在哪 | Mac 上，客机接触不到 | 客机里 |
| 客机里拿到管理员权限后 | 绕不过。客机里没有可以关掉的东西 | 可以用一条命令关掉防火墙或改规则。现在客机账户可以开管理员，这个风险是现实的 |
| 代理的节点和凭据 | 只在 Mac 上 | 要放进客机 |
| 代理断开时 | 门禁关闭，客机收发都断 | 依赖客机内的规则生效 |
| 维护 | 一套，在 Mac 上 | 每台客机一套，随系统更新要重新核对 |
| 对 Mac 的影响 | 不改 Mac 的防火墙，不需要管理员权限 | 不影响 Mac |
| 客机可以带着网络规则整体迁移 | 不能，规则在 VMac 里 | 能 |

设想方案要达到的三件事，代理断开即断网、域名解析不泄漏、UDP 不直连，现状都已做到，并且每次启动都有检查在验证。唯一做不到的是「网络规则跟着虚拟机快照走」，而 VMac 的客机本来就只在 VMac 里运行，用不上这一点。

所以网络层不改实现。要做的只是界面：在工具栏的状态胶囊和「环境检测」页里，把「代理断开，客机立即断网」这件事讲清楚，让它看得见。

## 6. 子项目和顺序

每一项单独设计、单独实现、单独打包验证。

| 顺序 | 子项目 | 内容 | 依赖 |
|---|---|---|---|
| 0 | 三项验证 | 画面跟随窗口是否稳定；声音设备和共享目录是否妨碍保存状态；全屏后四指轻扫和 `⌃←/→` 是否能切换 | 无。结果决定后面几项怎么做 |
| 1 | 界面：视觉基础和外壳 | 配色、组件、工具栏、桌面与控制中心两种状态、全屏按钮和快捷键、全屏下呼出控制中心 | 无 |
| 2 | 界面：页面重组 | 导航合并，各页面重做，资源设置移入「虚拟机与磁盘」 | 1 |
| 3 | 画面跟随窗口 | 自适应分辨率，全屏体验打磨 | 0、1 |
| 4 | 视觉锚点 | 客机壁纸、强调色、全屏标识线 | 1 |
| 5 | 共享与传输设置 | 开关集中，上限可调 | 2 |
| 6 | 共享文件夹 | VirtioFS 单文件夹共享，边界检查同步修改 | 0、5 |
| 7 | 音频 | 输出和麦克风，后台自动静音 | 0 |
| 8 | 挂起和恢复 | 保存和恢复状态，恢复后重新检查网络 | 0、7 |
| 9 | 小项 | 富文本剪贴板；安装时指定磁盘、内存、CPU；克隆方式核实 | 2 |

顺序 0 的三项验证成本低，但会决定 3、6、7、8 的做法，所以放在最前面，和顺序 1 同时进行。

## 7. 第一期的结果和遗留

界面第一期（视觉基础和外壳）已完成，并在真机上核对过：新配色、水獭标志、工具栏、桌面与控制中心两种状态、自动启动、浮动提示、拖入描边、全屏（工具栏自动收起）。

期间的三项决定：

- **只做浅色。** VMac 始终是蓝白配色，不做深色模式。
- **标志改为水獭。** 用的是用户提供的图，母版在 `assets/branding/vmac-otter.png`。
- **全屏切换手势可用。** 路线图「顺序 0」里的第三项验证已通过；另外两项（保存状态的兼容性、画面跟随窗口）还没做。

留到第二期一起处理的小问题：

1. 概览里的小卡片，「处理中」和「需留意」的颜色和状态标签相反。
2. 出错提示会被后一条普通提示顶掉；拖出多个文件时，中间一个失败会被最后的「已拷出 N 项」盖住。
3. 用工具栏开关回到桌面后，侧栏的选中项和页面可能对不上；开关在无事可做时看起来仍是可点的。
4. 工具栏的传文件按钮失败时没有提示。
5. 无用代码：侧栏的「窄侧栏」分支、侧栏里为深色准备的重新取色逻辑、`attempted: false` 这个固定参数、仍在写入但不再读取的 `vmac.windowAppearance`。
6. 个别动画时长不在 120、200、320 毫秒三档里。
7. 卡片仍是白底加边框，另有两处 9 像素圆角没有改。
8. 窗口标题隐藏后，「更新待完成」的提示看不到了。
9. 客机桌面状态下窗口关闭或最小化时，`⌘Q` 和 `⌘H` 没有反应。
10. 应用图标缺少最大的几档尺寸。
11. 浮动提示只有一行，过长的错误信息看不全。
12. 「设置 → 外观」里除主题以外的选项（字号等）还在旧页面里，第二期并入「通用」。

## 8. 第二期（上）的结果和遗留

界面第二期（上）——导航和页面合并——已完成：侧栏十个页面分三组，旧「设置」的各个分组并入对应页面，新增「共享与传输」「通用」两页和状态胶囊的浮层；第 7 节的十二项遗留全部处理完。

期间的决定：

- **旧「设置 → 通用」只留一项。** VMac 里只显示「Claude 终端启动命令」（手机远程新建会话时用到）；时间格式、键盘习惯、流畅优先、工作台快捷键表只作用于共用工作台，VMac 的原生客机窗口用不到，不再显示。
- **「显示」只留四项。** 界面字号、指针光标、字体平滑、减少动态效果；主题、配色、代码字号和从 Codex 同步不再显示。
- **卡片一律无边框。** 概览的小卡片、检测页顶部的三个数字和各页的卡片都是灰色底、无边框，卡片里面的小块用白色。
- **设置随时重新读取。** 每个嵌入的表单保存时提交的是整份设置，所以外壳在进入有表单的页面前、以及每个后台任务结束时重新读取一次；内容没变时不重建表单，正在填写的内容不会丢。
- **离开前询问。** 打开桌面、启动、重启、停止，和切换页面一样，都会先问是否放弃未保存的修改。

留到第二期（下）一起处理的小问题：

1. 设置内容变化时，同一页上的所有嵌入表单都会重建，保存其中一个可能清掉旁边填到一半的另一个。
2. 保存任务进行中离开页面，问的是「放弃尚未保存的修改？」，其实保存已经在进行。
3. 状态浮层的防重开判断依赖关闭动画的时间，很快地连点两下可能又弹出来。
4. 仍在用旧名字的文案：`settings.jsx` 里的「虚拟机管理」、`Cage.swift` 里的「请在虚拟机管理中切换」、`account.jsx` 里的「设置 → 账户」（五处）、后端提示里的「网络与代理设置」。（已处理：这些提示在 VMac 里改说现在的页面名，共用工作台仍是原来的说法；页面端的规则是 `placeName`，后端是 `internal/version/places.go`，有测试保证两边的页面名一致。）
5. 门禁关闭时，状态浮层的「出口」一行显示的是上次的出口，没有「上次检测」字样。
6. 「环境与恢复」页里还是旧工作台的文案（「当前项目」「侧栏的加号」等）。
7. 「界面字号」只对嵌入的旧分组生效，VMac 自己的页面是固定字号；是否保留这个选项在第二期（下）决定。
8. 存储恢复期间表单被禁用，但没有说明原因。
9. 自动启动的开关存在网页存储里，其他开关存在应用自己的偏好里；可以统一到后者。
10. 零碎：`/macos/disk` 读取失败后不重试；代理线路页可能连续弹两个确认；还剩三处 9 像素圆角；出错提示在窗口变宽后不会重新排版；`autoStartEnabled(localStorage)` 取 `localStorage` 的那一步不在保护范围内。

还没有在真机上核对的：全屏时工具栏自动收起，状态浮层是否正常。

## 9. 不做的事

- 不把代理核心和防火墙规则搬进客机。
- 不给客机接 vmnet 或其他第二块网卡。
- 不截走系统快捷键和系统手势，它们留给 Mac，用来在两个系统之间切换。
